# Responsiveness review and installed build, 2026-09-09

Foreground activation previously reached `UpdateGui` through `TThread.Queue`, which executes inline when called from the VCL thread. List refresh then enumerated windows and accessed lazy `TAppInfo` metadata. The command-line getter uses synchronous WMI. Eight equivalent native Windows WMI probes took 6.44 to 7.71 seconds, with a 6.98-second median. This is evidence of a blocking path consistent with the reported pause; it is not a captured stack trace of the user's exact freeze.

The new `ActiveAppView.WindowSnapshots` service owns an inventory worker and a metadata worker. Inventory/configuration reads happen outside the VCL thread. Potentially blocking WMI, shell-property, and icon calls run in a cancellable helper process with a 15-second deadline. Neither worker borrows form-owned `TAppInfo` instances. The form receives copied records through a coalesced Windows message and applies their display values. Repeated foreground requests therefore do not execute enumeration or metadata retrieval inline.

List synchronization compares stable identities, leaves unchanged rows untouched, and applies insertions, removals, renames, and reordering while restoring selection and the top visible row. This retains the existing VCL list controls and keyboard workflows. Selected-window details arrive asynchronously. An explicit command-line copy has its own retained request, validates HWND/PID/process-start identity, permits retries after metadata failure, and discards a delayed result if the clipboard has since changed.

Retained regressions cover deferred/coalesced refresh, real desktop collection, real isolated metadata retrieval and cancellation, unchanged native list mutations, selection and scroll preservation, reordered and duplicate-caption rows, delayed selection results, copy retries/supersession, removal of obsolete snapshots, and chat recovery following a failed collection. Behavioral defects were reproduced before their fixes; evidence files named `*-red.out` and `*-green.out` remain in the temporary candidate directory. Cold creation of native controls is measured separately from refreshing an already-created GUI.

## Follow-up candidate: selective metadata and slow GUI diagnostics

After the maintainer reported improved foreground behavior and approved this follow-up, T-052 split metadata into identity, command line, and icon fields. Prefix matching requests identity first and queries the command line only when an empty AppUserModelID requires that fallback. Hidden, terminal, and Explorer rows receive no unused prefix metadata. Selected-window identity/icon results can publish before the separate WMI request. Explicit Copy requests fetch only the command line. Successful command lines are reused within the current snapshot inventory only when both PID and a known process start time match. HWND-specific fields and helper failures are not shared across windows.

The existing inventory and metadata workers, coalesced message delivery, helper deadline, and cancellation remain in use. This introduces neither an additional worker nor an unbounded process cache. Command-line completion now has independent attempt/error state, so later identity/icon results cannot erase a failed Copy completion before the GUI consumes a coalesced update. Review found that race; a retained failing regression preceded its correction.

T-053 times the foreground handler and complete snapshot-message application with a stopwatch. Operations below 50 ms do not format or append a diagnostic. At most 128 slow samples plus one overflow notice are retained, containing operation, elapsed time, and window count. The existing buffered logger writes these records to `startup-profile.log` at normal shutdown. The new timing hooks perform no file I/O. Their test covers the threshold, storage cap, other-log isolation, and a controlled 60 ms workload through the actual activation handler.
